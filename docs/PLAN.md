# Plan after 0.5.0

Where things stand: the library, the DevTools extension (Chrome, Edge, Firefox), the relay panel
for any app, Vite/Next.js/Webpack entry points, Vitest and Playwright integrations, a CLI with
budgets and root causes, a scale test that proves large apps no longer freeze, React 18 and 19
in CI, and Web Store assets generated by script. 0.5.0 is ready to tag.

Each milestone below ends green (`npm run check`, `npm run e2e`, `npm run e2e:next`) and merges as
one fast-forward. Ordered by value over risk; sizes are working days.

## O. Ship 0.5.0 and the listings (½ day, mostly yours)

- Tag `v0.5.0`: the Release workflow publishes to npm and attaches the three extension zips.
- Chrome Web Store: new item from `dist-extension/chrome.zip`, listing from `extension/store/LISTING.md`,
  media from `extension/store/media/`, privacy URL from `PRIVACY.md`. Unlisted first, then public.
  Edge Add-ons takes the same zip. Firefox AMO takes the firefox zip; its reviewers want build
  steps, which `extension/README.md` has (the vendor scripts are unminified).
- Code: a *Report a problem* link in the Settings drawer that opens a prefilled GitHub issue with
  the extension version, `info()` (React version, options, overhead) and the current export
  attached as text.
- Walk `extension/store/QA.md` on a real large app once (injection on, side panel, flash, source
  links, settings persistence) and fix what it turns up.

Done when: the listing is live (unlisted) and the issue link produces a usable report.

## P. Correctness on modern React (2–3 days)

The verdicts are tested on hand-written memo/hook examples. Production apps use React Compiler
output, `use()`, transitions, Suspense, RSC client boundaries, external stores with selectors and
render props, and each can produce a wrong "avoidable" or hide a real one.

- A fixture matrix in `test/fixtures/`: a component compiled by `babel-plugin-react-compiler`
  (its `useMemoCache` slots must not be diffed as state), `use(promise)`, `startTransition`,
  Suspense fallback → content, `useSyncExternalStore` with a selector, render-prop `children`,
  `forwardRef` + `memo`, a class with `shouldComponentUpdate`, `use-context-selector`.
- Decide the verdict for each, fix `analyze` / `buildReport` where it disagrees, and write the
  verdict table into the README ("What counts as avoidable").
- The example app gets the same cases on a `/modern.html` page so the extension and the panel are
  exercised on them too.

Done when: every fixture asserts its verdict, existing tests unchanged, the table is in the README.

## Q. Jest and the peer range (2 days)

- `rerender-lens/jest`: a `setupFilesAfterEnv` helper and a reporter class using the same JSONL
  hand-off as the Vitest integration; exercised by an in-repo Jest run (jest, jest-environment-jsdom,
  babel-jest) as a CI job so it cannot rot.
- React 17: `test/helpers.ts` picks `react-dom/client` or legacy `ReactDOM.render` plus `act` from
  `react-dom/test-utils`; `npm run test:react17` joins CI. If 17 needs more than a day of fiber
  differences, change the peer range to `>=18` instead of carrying an untested claim.

Done when: Jest and React 17 (or the narrowed range) are covered by CI jobs.

## R. Panel: several apps on one relay, and a timeline (2–3 days)

- The relay assigns each app an id and stamps messages; the panel shows an app chooser chip when
  more than one is connected and keeps state per app. Commands carry the target app.
- A timeline strip above the tree: commits over time as a sparkline with avoidable counts;
  clicking scrolls the Commits view there, brushing filters the tree and Offenders to that window.
  This answers "what happened while I typed".
- Verify the DevTools panel and the side panel share per-origin settings both ways.

Done when: an e2e runs two apps on one relay; unit tests cover the timeline selection.

## S. The docs site as the product page (1–2 days)

- Landing with the recording, a "60-second start" per bundler (Vite, Next.js, Webpack, anything via
  the relay), the verdict table from P, CLI and CI guides, and an API reference generated by
  typedoc. A hosted panel demo (`panel.html?demo`, with a flood toggle) on Pages.
- `npm run docs:media` runs in the Docs workflow on release tags so screenshots never go stale.

Done when: the site answers "how do I start with my bundler" without opening the README.

## T. Hardening (1 day)

- Relay: require `--token` when `--host` is not loopback; send the token as a query parameter on
  the SSE stream and a header on POST; the panel URL carries it.
- Extension: make `web-ext lint` warnings fail CI where they are ours; re-check that no path uses
  `eval` outside the DevTools API; document the CSP.
- Perf: a nightly job runs the scale e2e at 3k / 10k rows with tighter budgets and posts
  `maxCommitMs` per size as a CI annotation, so a regression shows up before a user does.

## Not planned

React Native (no DOM, no DevTools panel path), legacy browsers, readable names in production
builds, a hosted relay.

## Order

O → P → Q → R → S → T. O is mostly your actions; P carries the most product risk and should go
first among the code milestones. R and S can swap depending on whether feedback from the listing
asks for panel features or onboarding.
