# rerender-lens

React re-render debugger. See README.md for the public API.

## Commands

- `npm test` (vitest, jsdom), `npm run typecheck`, `npm run build` (tsup for `dist/` and the panel, then `scripts/build-vendor.mjs` for the three injectable `extension/vendor/rerender-lens.*.js` scripts, then `scripts/copy-panel.mjs`), `npm run lint:pkg` (publint + attw).
- `npm run build:ext` packages `extension/` into `dist-extension/` (Chrome/Edge/Firefox zips; syncs the manifest version from package.json).
- `npm run check` runs all of the above and is `prepublishOnly`.
- `npm run e2e` (Playwright, Chromium with the extension loaded against the example app; needs `npm run build` and `npm --prefix examples/vite-react install` first).
- `npm run lint:ext` (web-ext lint on the Firefox package), `npm run build:docs`, `npm run docs:media` (docs screenshots), `npm run store:media` (Web Store screenshots + promo tiles into `extension/store/media/`).
- `npm run test:react18` / `npm run test:react17` install that React into `.react18/` / `.react17/` (gitignored) and run the unit suite against it through `test/react-compat.config.ts` (aliases `react`, `react-dom` and the JSX runtimes; `REACT_COMPAT_DIR` points elsewhere). Both run in the `react18` CI job. The harness is version-agnostic: `test/react-act.ts` takes `act` from `react` (18.3+) or `react-dom/test-utils`, and the config aliases `react-dom/client` to `test/react17-client-shim.ts` when the target React has no root API. Tests that need a newer React are guarded with the flags in `test/react-version.ts` (`HAS_REACT18_HOOKS`, `HAS_CONTEXT_VALUES`, `HAS_UPDATERS`, `HAS_REACT19`) rather than deleted; never call `React.act` directly in a test, import `act` from `./react-act`.
- `npm run test:jest` (`scripts/jest-check.mjs`) runs the Jest app in `test/jest/` twice against the **built** package (`npm run build` first): once with `budget.fail.json` (`{"*": 0}`), where the tests pass but the reporter must exit non-zero and print the ranked fixes, and once with `budget.pass.json`, where it must exit 0. Its own CI job (`jest`). Vitest never sees those tests: `test/jest/*.jest.test.tsx` does not match `test/**/*.test.ts`.
- `npm run check` runs the tests before `build`; after changing `extension/src/panel.ts` run `npx tsup` first or the jsdom tests read a stale `extension/panel.js`.
- `npm run dev:example` builds the library and starts `examples/vite-react` on port 5199 (`/` runs the library itself, `/plain.html` does not, for testing injection; `/scale.html?rows=N` is the scale test with a readout of `info().overhead` and `info().truncated`, used by the e2e suite).

## Layout

- `src/types.ts` — public types, `MARKER` (`rerenderLens` static).
- `src/diff.ts` — `deepEqual`, `classify`, `AVOIDABLE_KINDS`, `diffRecords`, `firstDifferentPath`. Pure.
- `src/report.ts` — `buildReport` (trigger/avoidable/reasons), `printReport`, `summarize`. Pure.
- `src/state.ts` — options + enabled flag on `globalThis[Symbol.for('rerender-lens.state')]`; `dispatch` prints (with the per-component cap) and notifies.
- `src/fiber.ts` — the core: `ensureDevtoolsHook`, `attach` (wraps `hook.onCommitFiberRoot` and `hook.inject`), `onCommit` (tree walk + analysis), instance registry (`fiberById`, `hostNodesOf`, `fiberForNode`), `sourceOf`, `getRenderers`.
- `src/tracker.ts` — `init`/`configure`/`disable`, `shouldTrack`, `getDisplayName`, `track`.
- `src/hook.ts` — `useWhyRerender`. `src/notifiers.ts` — collector. `src/overlay.ts` — in-page highlight/flash DOM.
- `src/devtools.ts` — postMessage bridge (protocol 2): `createDevtoolsNotifier`, `window.__RERENDER_LENS_DEVTOOLS__` (`replay`, `pull`, `info`, `configure`, `highlight`, `inspect`, ...), `serializeOptions`.
- `src/inject.ts` — entry of the injectable library (everything but `useWhyRerender`, which needs `react` as a module). `scripts/build-vendor.mjs` builds it as three classic scripts, `vendor/rerender-lens.core.js` (types, version, diff, report, state, overlay), `vendor/rerender-lens.engine.js` (fiber, tracker, hookNames) and `vendor/rerender-lens.js` (bridge, notifiers, `window.RerenderLens`); later parts import earlier modules through `globalThis.__RERENDER_LENS_PARTS__`, so no module may be imported by an earlier part than the one that owns it. `src/version.ts` — `VERSION` from a build define.
- `src/hookNames.ts` — opt-in custom hook name replay. `src/fixes.ts`, `src/causes.ts`, `src/sessions.ts`, `src/budget.ts` — pure ranking (with snippets and provider attribution), commit/root-cause analysis (`rootCauseOf` walks `parent` links inside one commit, `analyzeCommit`, `contextAttribution`, `cascadeTree`, `rootCauseSummary`, plus `groupByCommit`/`rankRootCauses`/`formatRootCauses` across commits), summary/compare and budget helpers. They are typed over `ReportLike` (`src/types.ts`), the structural subset that both a live `RenderReport` and the panel's serialized `Report` satisfy: `extension/src/panel.ts` imports `fixesFor`/`rankFixes`, the `causes` helpers, `summarizeSession`/`compareSessions`, `firstDifferentPath`/`diffLeaves` and `summarize` from `../../src/*` and tsup bundles them into `extension/panel.js`, so there is one implementation; the panel only wraps `analyzeCommit`/`rootCauseSummary` to add `receivedAt` and its per-commit `fixes`. `causes.ts` imports `AVOIDABLE_KINDS` from `diff.ts` (not `fixes.ts`) so `formatFixes` can call `formatRootCauses` without a cycle. `src/cli.ts` — the `rerender-lens` bin (`fixes`, `causes`, `summary`, `compare`, `budget`).
- `src/vite.ts` — `rerender-lens/vite` plugin (virtual setup module + `<script type="module">` prepended in dev). `src/setup.ts` — `rerender-lens/setup` side-effect entry (Next.js `instrumentation-client`, Webpack entry arrays).
- `src/relay.ts` — `rerender-lens/relay`, the SSE + POST relay behind `rerender-lens panel` (serves `panel/`). The library side is the `relay` option in `src/devtools.ts` (shares `runCommand` with the BroadcastChannel); the panel side is `createRelayClientTransport` in `extension/src/panel.ts`. `test/sse.ts` is a fetch-based EventSource for Node.
- `src/playwright.ts` — `rerender-lens/playwright` (injects `dist/rerender-lens.iife.js`, copied by `scripts/copy-panel.mjs` after tsup). `src/runner-report.ts` — everything the test-runner integrations share: `setupRerenderLens`, `slim`, `readRun`, `createRunFile`, `finishRun` and `RunReporterCore`; workers append JSONL to the file named by `RERENDER_LENS_OUT` (the reporter creates it in the main process before any worker spawns). `src/vitest.ts` + `src/vitest-setup.ts` and `src/jest.ts` + `src/jest-setup.ts` are the thin runner-specific wrappers (`rerender-lens/vitest`, `rerender-lens/jest` and their `/setup` entries); the Jest reporter differs only in its constructor (`(globalConfig, options)`), its event names (`onRunStart`/`onRunComplete`) and in failing the run through `getLastError()`. `src/jest-setup.ts` reads `afterAll` and `expect` off `globalThis` so the package never imports `@jest/globals`.
- `attach` is guarded by a symbol on the hook so two bundled copies of the library (setup entry + main entry) do not both wrap `onCommitFiberRoot`.
- Tests must pass in a checkout without `dist/` or `extension/vendor/` (`npm run check` runs tests before the build): `test/vite.test.ts` aliases `rerender-lens` to `src/index.ts` because the example links the package, whose exports point at `dist/`; the Playwright helper test injects a stand-in through the `bundle` option.
- `scripts/build-docs.mjs` renders README + extension README to `docs-site/` (GitHub Pages workflow); `scripts/docs-media.mjs` captures `docs/media/*` with Playwright (its ffmpeg cannot encode GIF, so the recording stays webm).
- `examples/vite-react` — dogfood app (links the library via `file:../..`, so `npm run build` first).
- `examples/next` — Next.js App Router app: `instrumentation-client.ts` imports `rerender-lens/setup`, `.env.development` sets `NEXT_PUBLIC_RERENDER_LENS_RELAY`. `npm run e2e:next` (`e2e/next.config.ts`, `e2e/next.spec.ts`) starts `rerender-lens panel --port 4142` and `next dev -p 3005` and checks the relay panel connects, replays, and highlights back into the app; the default `npm run e2e` matches only `extension.spec.ts`. `next dev` rewrites `examples/next/tsconfig.json` and re-adds `AGENTS.md`/`CLAUDE.md` there; commit them as generated.
- `src/setup.ts` reads `process.env.X` through static member expressions only: bundlers inline those and never a dynamic `process.env[key]`.
- Several apps on one relay: each app stream gets an id (`a1`, `a2`, ...) and a label (`?label=` from the library, `location.host + pathname`; falls back to the Origin header). The relay greets the app with `{ __rerenderLensRelay: true, app }`, the library remembers it and posts to `/message?app=<id>`, and the relay stamps `app` on what that app sends to panels. A command carrying `app` goes to that one app; without it, or when that app is gone, it goes to all of them, so a panel or library that knows nothing about ids behaves as before and the protocol stays at 2. `appList()` and `/status` expose the roster.
- Relay handshake: the relay sends `{ type: 'relay', payload: { apps, list } }` to a panel as soon as its stream opens and on every app connect/disconnect; `createRelayClientTransport` sends its first `info` only after that greeting (replies are forwarded only to panels already connected). `npm run test:built` runs `test/vendor.test.ts` after the build (it skips without `extension/vendor/`).
- `extension/` — MV3 DevTools extension. The panel is TypeScript (`extension/src/panel.ts`, one file, `export {}`-free module via `declare global`); `npm run build` (tsup, third entry) writes the committed `extension/panel.js`, which tests and load-unpacked use, and CI fails if it is stale. Everything else in `extension/` is plain JS. `panel.js` exposes `RerenderLensPanel.createPanel(root, transport)` plus pure `analysis` helpers (`fixesFor`, `rankFixes`, `rootCauseOf`, `analyzeCommit`, `rootCauseSummary`, `diffLeaves`; all re-exported from `src/`, `analyzeCommit`/`rootCauseSummary` being the panel's wrappers); `panel.html?demo` runs it with sample data, `?demo&flood=N` with N synthetic reports; `background.js` routes messages, keeps the badge and registers per-origin scripts (`shared.js`); `inject.js` bootstraps the injected library; `sidebar.*` is the Elements sidebar; `popup.*` enables origins; `store/` holds listing/privacy/publishing docs.
- `scripts/` — `build-extension.mjs` (+ `zip.mjs`, dependency-free zip writer), `sync-version.mjs`, `jest-check.mjs`.
- `test/jest/` — the Jest app: `jest.config.cjs` (jsdom, babel-jest, the reporter and setup resolved by package name through the exports map), `setup.ts` (the `setupFilesAfterEnv` line, re-exports `lens` for the assertions), `helpers.tsx` (react-dom/client + `act`), three `*.jest.test.tsx` fixtures (unstable props, a rebuilt context value, and a clean component that must report nothing) and the two budget files.
- `e2e/` — Playwright config and spec.

## Design decisions

- Fiber inspection instead of wrapping element types. The earlier wrapper design broke Fast Refresh (a wrapped component never received its edits, because refresh families are keyed by the original function and Vite's plugin-react injects module-local `$RefreshReg$`, so there is no way to join a family from outside). Reading fibers is what React DevTools does; it needs no import-order tricks and no `jsxImportSource`.
- "Did it render" = `flags & PerformedWork` (1). Skip a subtree when `fiber.child === fiber.alternate.child` (React reused the children, so nothing below rendered). Fresh fibers always have fresh flags; stale ones are only reachable through a skipped subtree.
- Hot reload detection: `fiber.type !== fiber.alternate.type` on a rendered component (React assigns `family.current` to the work-in-progress type in `createWorkInProgress`). Such a commit is skipped when `ignoreHotReload` is on.
- Hook diffing only looks at nodes with a `queue.lastRenderedReducer` (state) or `queue.getSnapshot` (external store). `_debugHookTypes` is used for labels only when its length matches the node count after removing node-less hooks (`useContext`, `useDebugValue`, `use`), because `useTransition`/`useSyncExternalStore` create several nodes per call.
- `useState`/`useReducer` changes are trigger `state`; `useContext`/`useSyncExternalStore` are `hooks`.
- Console prints only avoidable reports unless `logAll`; the notifier gets everything.
- Mount is never reported; StrictMode's double render is one commit and reports once.
- Bounded work per commit (a large app froze otherwise): `onCommit` opens one `beginDiffScope()` so `deepEqual` memoizes compared pairs across every component of the commit and stops (reporting `different`) after a visit budget; it reports at most `MAX_REPORTS_PER_COMMIT` (200) components and stops after `COMMIT_TIME_BUDGET_MS` (25 ms), counting the rest in `state.truncated` / `info().truncated`. `serialize` caps breadth at `SERIALIZE_MAX_ENTRIES` (100) per container, total nodes at `SERIALIZE_MAX_NODES`, treats typed arrays / ArrayBuffer / Node / Promise as leaves, and defaults to depth 4. `sourceOf` caches per `_debugStack` object. The instance registry prunes on growth thresholds, not on every report. Overlay boxes are measured before any DOM append and capped at 100 per call.
- Window posts of reports are gated: `createDevtoolsNotifier` only posts `report` messages on a real window after a `{ __rerenderLensReady: true }` message (content.js sends it on load and whenever it sees a `hello`) or a `replay()`; `hello`/`clear` always post. Targets without `addEventListener` (tests) are treated as listening. BroadcastChannel and relay sinks are unaffected.
- The injected library (`inject.js`) runs with `includeState: false`: snapshotting every hook/context/state value per report is the largest per-commit multiplier on big apps; Settings can turn it on per origin.
- `commitId` is assigned per `onCommit` call that produced at least one report. `source` comes from `_debugSource` (React <= 18) or the first non-React frame of `_debugStack` (React 19).
- React renderer info: hooks created by react-refresh never fill `hook.renderers`, so `attach` wraps `hook.inject` and records what react-dom passes. This is why `init` should run before `react-dom` loads if you want the React version and dev/prod detection.
- Extension: dynamically registered content scripts (injection, relay on user-enabled origins) need real host permissions, so the manifest declares `host_permissions` for the local hosts and `optional_host_permissions` for everything else; nothing beyond local hosts is granted until the user enables a site. Injection is off until enabled per origin. If the extension's hook is created before React DevTools installs its own, React DevTools bails out; documented as a known limitation.
- Context provider lookup walks `fiber.return` for tag 10 whose `type === context` (React 19, the context object is the provider type) or `type._context === context` (React <= 18). `changedKeys` is a shallow key diff of plain-object context values. `commitPriority` maps the Scheduler priority React passes as the third argument of `onCommitFiberRoot` (1 immediate ... 5 idle); transitions run at `normal`. Elements serialize as `{ $type: 'element', name, key?, props }` so the panel can diff children.
- Custom hook names (`src/hookNames.ts`, opt-in `resolveHookNames`): the component function is re-run once per type with a stand-in dispatcher installed on the `currentDispatcherRef` react-dom injects (`.H` in React 19, `.current` before). Each primitive records `new Error().stack`; frames between our marker (`__rl_`) and the component frame are the custom hooks. Values come from the real hook nodes (node counts per primitive in `HOOK_NODE_COUNT`); a node-count mismatch or a throw discards the result. Because the replay runs the component body, anything it does during render (logging, assigning outer variables) happens once more.
- `updaters` come from `root.memoizedUpdaters`, which React fills in dev when a DevTools hook exists. Effect-loop detection: the commit's updaters intersect the previous commit's rendered components and less than 50 ms passed. Suspense resolution: a tag-13 fiber whose `memoizedState` went non-null → null.
- React Compiler: `useMemoCache` keeps its slots in `fiber.updateQueue.memoCache` (`{ data: unknown[][], index }`) in React 19, not as a hook node and with no `_debugHookTypes` entry, so it never reaches the hook diff; `isCompiledFiber` checks for that cache and the report carries `compiled: true`. A compiled component with trigger `parent` and no prop changes is not avoidable (cache hit, nothing to fix); with new-but-equal props it still is (the compiler compares inputs with `!==`), minus the `React.memo` advice. Other verdict rules from the modern-React matrix (`test/modern.test.ts`): `ref` as a prop (React 19) with two distinct `{ current }` objects is `deep-equal` on `ref` (`.current` is ignored: React mutates it on re-attach); a `parent`-triggered render under a Suspense boundary that switched from fallback to content in the same commit is `revealed` and not avoidable; `useDeferredValue` nodes are diffed only through dev labels (they have no queue) and a commit containing such a catch-up is never labelled `effect-after-commit`.
- `selfDuration` = `actualDuration` minus the direct children's `actualDuration` (React resets it to 0 in `createWorkInProgress`, so bailed-out children add nothing); `treeDuration` is the raw value. `memoized` comes from the fiber tag (14/15) or `stateNode.isPureReactComponent`.
- Injection "defer" mode is a one-line flag script (`inject-deferred.js`) listed before `inject.js`; the injector then creates/wraps the hook in a `setTimeout(0)`. Kept as a per-origin toggle rather than a default because a synchronous `<script>` in `<head>` could load react-dom before the timer fires.
- Panel lists are windowed (`virtualList` in panel.ts): fixed row heights (`ROW_H` 22px tree, `ITEM_H` 20px stream, mirrored in panel.css), absolutely positioned rows inside a spacer, overscan 8. With no layout (jsdom) the viewport falls back to 800px so tests still see rows.
- The panel has one relay transport (`createRelayTransport(io)`) and two `TransportIO` adapters: `devtoolsIO` (`inspectedWindow.eval`, expressions per `BridgeCommand`) and `standaloneIO` (`chrome.scripting.executeScript` with a closure-free `pageBridgeCommand` in the MAIN world, `chrome.tabs` for navigation/active tab). `sidepanel.html` and `panel.html?tabId=` boot standalone; `panel.html` inside DevTools boots the DevTools adapter. Standalone needs host access to the tab's origin.
- Panel scale: `MAX_PER_COMMIT` (500) reports kept per commit (first arrivals, i.e. ancestors); `analysisFor` memoizes `analyzeCommit` per commit by report count; `rootCauseOf` takes a per-commit component index; summary totals are counters kept in `ingest`/`evict`. Above `THROTTLE_MIN_REPORTS` (200) buffered reports the non-tree left pane and analysis-backed details render at most every `LEFT_RENDER_INTERVAL` (250 ms) and the best fix every `BEST_FIX_INTERVAL` (500 ms); below it everything is synchronous so tests stay deterministic (above it, tests use `vi.useFakeTimers` + `advanceTimersByTimeAsync`). The parsed filter and `rankFixes` result are cached per data generation.
- Port protocol: content.js sends one `{ type: 'batch', items }` per macrotask (single messages still accepted); background forwards batches untouched and counts the badge per item; the panel unpacks them in order. `createRelayTransport` retries `info` with backoff (`SYNC_RETRY_MIN`/`MAX` 500 ms → 5 s, `SYNC_RETRIES` 20) until the page answers, cancelled on navigation/tab change/`dispose()`.
- Panel transport contract: only `subscribe` is required; every other method (`pull`, `configure`, `highlight`, `storage`, `originStatus`, ...) is optional and the panel degrades (tests and demo mode use partial transports). Reports are batched per animation frame; tests call `panel.flush()`.

## Testing conventions

- `test/setup.ts` calls `ensureDevtoolsHook()` before any test imports `react-dom`; otherwise react-dom never injects and no commits are observed.
- Synthetic-fiber tests in `test/tracker.test.ts` cover hot-reload suppression, bailout pruning and React 16 `effectTag`. `test/bridge.test.ts` covers protocol 2.
- Extension runtime scripts are tested by evaluating them with `new Function` against `extension/test/fake-chrome.ts`; `background.js` returns its top-level functions that way. Await `settle()` twice after a UI change that goes through the background's async message handler.
- Anonymous arrows have no name; use `track(fn, 'Name')` or a named function. `memo(function X)` gets renamed by the dev transform (`X2`); set `displayName` on the memo.
- Instance ids are a global counter across tests: read the id from a report rather than assuming `1`.
